WHY THIS PROJECT

把 Agent 的“能做”变成“可控地做”。

展示页先呈现运行证据，再解释实现机制。访客可以直接进入在线系统，观察审批、恢复和 trace 如何串成一条完整执行链。

01
CONTROL CONTRACT

把副作用放进策略门。

工具元数据声明 side effect、风险等级和审批要求，Agent 只能通过显式 policy gate 进入执行阶段。

requires_approval: true
02
DURABLE STATE

失败之后仍然知道下一步。

任务状态写入 SQLite checkpoint；服务重启后恢复待处理节点，而不是重新猜测已经发生过的动作。

checkpoint.resume()
03
TRACEABLE OUTPUT

每一次工具调用都能复盘。

trace id、参数、耗时、错误类型和人工决策写入 JSONL，支持在线调试和离线回放。

trace_id → event log

CONTROL CONTRACT

把安全边界写进执行协议。

这个项目的核心不是让模型“更敢做”，而是让执行器明确知道哪些动作必须暂停、谁可以批准、恢复时从哪里继续。

RECOVERY PATH

暂停、失败、重启，最终状态仍然可解释。

状态机和事件日志让恢复路径成为产品能力，而不是散落在异常处理里的隐藏逻辑。

A
PAUSE

在风险边界前停住。

遇到高风险工具调用时，系统保留上下文和计划，不提前执行副作用。

state: awaiting_approval
B
RESTART

重启后接着处理。

worker 恢复任务并读取最近 checkpoint；已完成的读取步骤不会被重复伪装成新结果。

state: resumed
C
AUDIT

从日志还原决策。

人工审批和工具结果保留在同一条 trace 中，方便排障、复盘与构造评测样本。

state: completed
