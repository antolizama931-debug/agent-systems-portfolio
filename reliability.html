WHY THIS PROJECT

不只评价答案，更评价执行过程。

展示页采用“运行预览 → 在线实验 → 场景矩阵 → 验收字段”的路径，访客可以先理解证据链，再直接运行一个可复现 case。

01
SCENARIO CONTROL

故障注入是可配置的。

将消息堆积、连接池耗尽、HTTP 500 和 timeout 作为明确输入，减少“偶然失败”带来的解释空间。

fault: http_500
02
BASELINE MATRIX

同一契约下比较策略。

ReAct、plan-execute、always-verify 与 adaptive-recovery 使用同一套工具和验收器，结果可横向对比。

policy × scenario
03
FINAL-STATE ORACLE

用系统状态完成验收。

成功率、重试次数、恢复率和未授权副作用都来自可检查的最终状态，不把模型自报结果当作事实。

expected ≠ narrative
